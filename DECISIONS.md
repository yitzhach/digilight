# Decisions

Anything BUILD.md leaves open or gets wrong: the simplest option that keeps its promises, logged here.

- **D-001 (Phase 0). Only `core` and `web` are scaffolded.** `gl`, `mcp`, `e2e/` and the other files in §4 are created in the phase that first needs them (§3: no file the brief does not ask for).
- **D-002. `zod` and `@preact/signals` are not installed yet.** Both are in the §4 stack; they are added when code first uses them (`zod` in Phase 1, signals in Phase 3).
- **D-003. Versions.** TypeScript 5.9 (§4 says 5; 7.x exists), Vite 7, Vitest 3, Preact 10, pnpm 10.28 (`packageManager`), Node 20+ (CI uses 22). No `wrangler` dependency: Workers Builds provides it and Phase 0 does not deploy.
- **D-004. Package names are `core` and `web`**, so `pnpm --filter web dev` works as the gate says.
- **D-005. Copied files are verbatim.** `bench/bakeoff/*.py`, `docs/bakeoff.md` and `fixtures/README.md` still name v1 paths (`testdata/photos`, `samples/`, `tools/bakeoff`, `docs/v2`). `common.py` builds paths from `REPO + '/testdata/photos/'` and `'/samples/dsc8382/'`; they must point at `fixtures/` and `fixtures/dsc8382/` before the scripts run (Phase 5 or 10). In `fixtures/`, `samples/painting.jpg` is `fixtures/painting.jpg` and `samples/dsc8382/` is `fixtures/dsc8382/`.
- **D-006. `wrangler.jsonc` `compatibility_date`** is the date of Phase 0 (2026-11-11).
- **D-007 (Phase 1). Dependencies.** `zod` 4 (core: the schema). Dev only, for tests and scripts: `jpeg-js` (decodes the fixture JPEGs and encodes the contact sheet; pure JavaScript, no native build) and `@types/node`. `core/tsconfig.json` covers `src/` with no Node or DOM types, so `src/` stays pure; `tsconfig.node.json` covers `test/` and `scripts/`.
- **D-008. Scripts run on Node's own TypeScript** (type stripping, Node 22.18+): `node scripts/x.ts`, no `tsx`. Imports carry `.ts` extensions (`allowImportingTsExtensions`, `erasableSyntaxOnly`).
- **D-009. Light colour table.** v1's Planckian spline is valid from 1667 K, so 1500 and 1600 K equal 1667 K. Display P3 uses the standard XYZ to Display P3 (D65) matrix (v1 had sRGB only). 6500 K is set to exactly (1, 1, 1).
- **D-010. Dramatic look: lamp brightness 1.1 to 1.0.** With §5 exactly, 1.1 gives `kappa` 0.66 on the lintel (the bakeoff mock used a different kelvin curve and a 256 px thumbnail: 0.73); 1.0 gives 0.72. BUILD.md §6 table updated. Measured: every look `kappa` 1 on the door; on the lintel gallery 0.95, raking-top 0.96, dramatic 0.72, the rest 1.
- **D-011. Not rendered yet:** relief (`relief.mode` is treated as off until Phase 4), sheen (a surface property: only with relief on), finish (Phase 6). The settings are in the schema and validated.
- **D-012. Defaults §6 leaves open:** sun `azimuth` 135 (upper left), `elevation` 30; `aim` range −2 to 3 like `pos`; the schema default `pos` is the "+ Add light" position. Unknown keys are rejected; missing settings get defaults.
- **D-013. `render(photo, doc, {width, region, kappa})`**: `kappa` is optional, so callers that split rows across workers compute the guard once (`guardKappa`). Returns `{data, width, height}` for the region. A photo whose long side is 512 or less is its own guard thumbnail (no upscaling).
- **D-014. `open(photo)` takes the file's SHA-256 from the caller** (the app or command line hashes the file); `core` does no hashing.
- **D-015. Commands not built in Phase 1:** `setRelief`, `measureRelief` (Phases 4, 5), `export` (Phase 3, it needs image encoding). `render` returns `{image, metrics}`. New lights are `light-N`, the smallest unused N.
- **D-016. Encode** starts its search from a 4096-bucket index of the threshold table: the same answer as the plain binary search (tested on every code), about three times faster.
- **D-017. Look strength mixes as `a(1 - s) + b s`**, so strength 1 gives the table's numbers exactly and 0 gives neutral exactly.
- **D-018. Metrics** compare shares (blown, crushed by display luma) with the photo at the same size and region; warnings when new blown is over 0.5% (the guard's limit), new crushed over 0.15% (v1's limit), or `kappa` < 1. v1's texture and thirds numbers are dropped. The guard judges at 512 px, so a render at another size can show a little over 0.5% with `kappa` 1.
- **D-019. Review rounds replace the contact sheet** (Isaac asked for an easy way to mark pictures and type or speak notes): `core/scripts/review.ts` + `review-page.html` write a page that saves each note to the artifact's database, where the next session reads it. Rebuilt from v1's lighting-round page (`tools/looks/review-template.html`).
- **D-020. Looks retuned from Isaac's round 1 notes** (too warm, highlights blown, spotlight too hard, window and daylight too subtle): lamps lower and cooler, room light higher and cooler, spotlight wider and softer, window closer with full falloff, daylight cooler. BUILD.md §6 table updated, goldens regenerated. On the door, gallery's near-white share (display luma >= 235) went from 8.1% to 2.7% (photo 0.07%). The lintel's white plaster still goes near-white under most looks; round 2 asks whether the guard should count from 240 (`guardKappa(photo, doc, at)` takes the level for comparison only; §5.7 still says 250). Raking looks stay subtle until Texture (Phase 4), as §6 says.
